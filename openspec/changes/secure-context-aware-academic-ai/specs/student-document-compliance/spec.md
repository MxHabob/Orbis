# Spec Delta

## Purpose

تمكّن هذه القدرة المستخدم المخوّل من معرفة اكتمال ملفات الطلاب ومتطلبات الأرشيف دون تخمين، مع إظهار النواقص المنطبقة فقط وبحدود الصلاحيات والنطاق التنظيمي للمستخدم.

## ADDED Requirements

### Requirement: تحديد نواقص مستندات الطلاب
The system MUST يقارن متطلبات مستندات المؤسسة المنطبقة على الطالب بالمستندات المرتبطة به، وألا يصنف متطلبًا غير منطبق على الطالب على أنه مستند ناقص.

#### Scenario: متطلب إلزامي منطبق بلا ملف مطابق
- **WHEN** يطلب مستخدم مخوّل فحص اكتمال ملف طالب
- **THEN** يعرض النظام المتطلبات المنطبقة التي لا يوجد لها مستند مطابق باعتبارها نواقص، ويميز المستندات المكتملة

#### Scenario: شرط المتطلب لا ينطبق على الطالب
- **WHEN** يكون شرط متطلب الوثيقة غير منطبق على خصائص الطالب
- **THEN** يستبعد النظام ذلك المتطلب من قائمة النواقص ويبين أنه غير منطبق عند الحاجة

### Requirement: البحث عن الطلاب ذوي النواقص
The system MUST يتيح للمستخدم المخوّل تحديد الطلاب الذين لديهم مستندات أرشيف ناقصة ضمن المؤسسة أو ضمن صف/نطاق مصرح به، مع نتائج قابلة للتقييد والترقيم.

#### Scenario: طلب قائمة بالنواقص ضمن صف مصرح
- **WHEN** يطلب مستخدم مخوّل الطلاب ذوي النواقص لصف ضمن نطاقه
- **THEN** يعيد النظام الطلاب الذين لديهم متطلب واحد أو أكثر منطبق وغير مستوفى، مع أسماء المتطلبات الناقصة

#### Scenario: لا توجد نواقص مطابقة
- **WHEN** لا توجد ملفات طلاب ناقصة ضمن المرشح والنطاق المطلوبين
- **THEN** يعيد النظام نتيجة فارغة واضحة مع العدد صفر دون اختلاق طلاب أو متطلبات

### Requirement: تقليل كشف بيانات الأرشيف
The system MUST يعيد الحد الأدنى من بيانات الطالب والوثيقة اللازمة لتوضيح النقص، وألا يكشف محتوى الملف أو رابط تنزيله عند الاستعلام عن اكتمال المتطلبات.

#### Scenario: عرض حالة النقص
- **WHEN** يعرض النظام نتيجة فحص النواقص
- **THEN** يقتصر الرد على معرّف مناسب للعرض واسم الطالب والنطاق وأسماء المتطلبات وحالة الاستيفاء، دون محتوى الملفات أو روابطها
