# Spec Delta

## Purpose

تضمن هذه القدرة أن أدوات الذكاء الاصطناعي تعمل بهوية المستخدم المصادق عليه وصلاحياته ونطاقه الفعلي، وألا تتحول صياغة الطلب أو موافقة النموذج إلى تفويض إضافي.

## ADDED Requirements

### Requirement: التحقق الخادمي من صلاحية كل أداة
The system MUST يتحقق من صلاحية الأداة المطلوبة في الخادم قبل تنفيذها، ويرفض التنفيذ إذا كانت الصلاحية مفقودة أو غير معروفة أو تعذر التحقق منها.

#### Scenario: المستخدم لا يملك الصلاحية المطلوبة
- **WHEN** يطلب المستخدم أداة تتطلب صلاحية لا يملكها
- **THEN** يرفض الخادم تنفيذ الأداة ولا يعيد بياناتها

#### Scenario: تعريف الأداة يفتقد صلاحية معروفة
- **WHEN** يستدعي النظام أداة مسجلة بلا صلاحية مطلوبة أو باسم صلاحية غير قابل للتفسير
- **THEN** يرفض الخادم التنفيذ افتراضيًا ويسجل رفض التفويض دون كشف البيانات

### Requirement: عدم رفع صلاحيات المستخدم عبر الوكيل
The system MUST يربط التفويض بهوية وسياق الطلب المصادق عليه، وألا يقبل ادعاءات الدور أو الصلاحية القادمة من رسالة المستخدم أو النموذج أو سياق الواجهة كبديل عن التفويض الخادمي.

#### Scenario: المستخدم يطلب تجاوز صلاحياته
- **WHEN** يطلب المستخدم أو النموذج تنفيذ أداة خارج صلاحيات المستخدم المصادق عليه
- **THEN** يرفض الخادم الطلب حتى لو وافق المستخدم في المحادثة أو وصف النموذج المستخدم بأنه مخول

#### Scenario: النموذج يقترح إجراءً يتطلب موافقة
- **WHEN** يقترح النموذج إجراءً يتطلب تأكيدًا بشريًا
- **THEN** لا يعد التأكيد وحده بديلًا عن الصلاحية الخادمية، ويعاد التحقق عند تنفيذ الإجراء

### Requirement: حصر بيانات الأدوات في المؤسسة والنطاق المصرح
The system MUST يحصر كل قراءة ينفذها الوكيل في المؤسسة الحالية ونطاق الوحدات التنظيمية والعلاقات أو التكليفات التي يسمح بها تفويض المستخدم.

#### Scenario: محاولة قراءة سجل من مؤسسة أخرى
- **WHEN** يحتوي طلب الأداة على معرّف سجل لا يتبع مؤسسة المستخدم
- **THEN** لا يعيد الخادم السجل ويعامل الطلب كغير مخول أو غير موجود وفق سياسة API

#### Scenario: معلم يطلب بيانات صف غير مكلف به
- **WHEN** يطلب معلم بيانات أو محتوى مرتبطًا بصف أو مادة خارج تكليفاته المصرح بها
- **THEN** لا يعيد النظام البيانات حتى لو أرسل النموذج معرّف الصف أو المادة
