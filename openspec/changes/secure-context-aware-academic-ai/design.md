# Design

## Context

راجع `proposal.md` للدافع والنطاق. توجد خدمة تنسيق AI في الخلفية تسجل أدوات ذات صلاحيات، وسياق هوية/تكليفات المستخدم، وخدمات للطلاب والمناهج والمستندات ومتطلبات الوثائق. فحص الصلاحية في مسار التنفيذ الحالي يتجاهل صلاحية غير قابلة للتفسير، كما أن سياق الصف والمادة المرسل من الواجهة يُستخدم لإثراء الطلب دون أن يكون مصدر تفويض. خدمة المستندات تستطيع تقييم متطلبات الطالب، لكن لا يوجد حاليًا فهرس بحث لمحتوى ملفات المناهج.

## Goals / Non-Goals

**Goals:**

- إنفاذ الصلاحيات ونطاق المؤسسة/الوحدة والتكليفات خادميًا في اكتشاف الأدوات وتنفيذها.
- إعادة استخدام خدمات الطلاب والمستندات ومتطلبات الوثائق والمواد والجدولة بدل تجاوزها باستعلامات غير مقيدة.
- دعم إجابات ومراجعات تعليمية مستندة إلى نصوص مناهج يمكن الوصول إليها، مع ذكر المصدر وبيان نقص المحتوى عند تعذر استرجاعه.
- إظهار حالة نواقص ملفات الطلاب ببيانات وصفية دنيا، وإنتاج مسودات أسئلة غير منشورة.
- إبقاء كمية السياق والنتائج محدودة ومجزأة، مع عدم تحميل كل مستندات المؤسسة إلى النموذج.

**Non-Goals:**

- منح صلاحية جديدة لمستخدم أو السماح لوكيل AI بتنفيذ تجاوز إداري.
- رفع اختبارات أو تغيير درجات/سجلات الطلاب تلقائيًا ضمن طلب إنشاء الأسئلة.
- إرسال محتوى وثائق الطلاب أو روابطها إلى نموذج AI عند حساب اكتمال الأرشيف.
- اعتماد نظام بحث دلالي خارجي أو مزود تخزين/نماذج جديد ضمن هذا التغيير.

## Decisions

1. **جعل تفويض الأدوات مغلقًا افتراضيًا وفي نقطة تنفيذ مشتركة.** يجب أن يملك كل تعريف أداة صلاحية معروفة، وأن تُرفض الأداة إذا غاب التعريف أو الصلاحية أو فشل فحص الصلاحية. يطبق الفحص نفسه عند كشف الأدوات للمحادثة وعند تنفيذها، مع إعادة التحقق قبل الإجراء المقترح المؤكد. هذا يمنع اختلاف مسارات التفويض أو الاعتماد على إخفاء الأداة في الواجهة. البديل المرفوض: الاكتفاء بتعليمات prompt أو فحص عند بداية المحادثة، لأن النموذج والعميل لا يمثلان حدًا أمنيًا.

2. **اعتبار سياق الواجهة تلميحًا لا تفويضًا.** تستخرج المؤسسة من `RequestContext`، ويستخرج دور الطالب وعلاقته بالمؤسسة من ربط الهوية الموثق، وتستخرج تكليفات المعلم من سجلات التكليفات/الجدول. يمكن الاستفادة من الصف والمادة المرسلين من الواجهة لاختيار سياق بين خيارات مصرح بها فقط؛ يجب إعادة التحقق من المؤسسة والتكليف قبل القراءة. إن تعذر إثبات السياق أو تعددت الخيارات يطلب الوكيل توضيحًا ولا يخمّن.

3. **تنفيذ أدوات القراءة عبر الخدمات القائمة.** فحص النواقص يستخدم تقييم متطلبات المستندات للطالب مع شروط الانطباق، ثم يجمع النتائج على صفحات محدودة. تكون استجابة الأداة ملخصًا وأسماء متطلبات وحالاتها، ولا تحتوي الملف أو رابط تنزيله. البديل المرفوض: البحث النصي الحر في المستندات أو إرجاع سجل المستند كاملًا؛ فهو أكثر كشفًا وأقل دقة في احتساب الشروط.

4. **إضافة استرجاع نصي مقيد لمناهج الأرشيف.** تخضع ملفات المنهج لحد المؤسسة والصلاحية ونطاق المادة/الصف، ثم يُستخرج النص أو يُبحث في نص مفهرس عند توفره، وتُرسل المقاطع المطابقة فقط إلى نموذج المؤسسة المُهيأ. يحتفظ كل مقطع بمرجع المستند/الوحدة ليظهر مصدر الإجابة. يجب استبعاد النصوص غير القابلة للاستخراج، والملفات المحذوفة أو غير المخولة، والإبلاغ بوضوح عند عدم كفاية المصادر. البديل المرفوض: تمرير الأرشيف كاملًا إلى النموذج أو اعتبار أسماء الملفات دليلًا على محتواها.

5. **توليد التقييم كمسودة محدودة.** أداة الاختبار الشفهي تولد حتى 50 سؤالًا من تكليف المعلم والمحتوى المسترجع، وتعيد المسودة للمحادثة فقط. النشر، حفظ الاختبار، تسجيل الحضور أو إدخال الدرجات يظل عملية منفصلة بصلاحية مستقلة وتأكيد خادمي. البديل المرفوض: ربط التوليد مباشرة بعمليات الحفظ أو التقييم.

6. **تحسين الأداء عبر ترشيح الأدوات واسترجاع محدود.** تُجهز تعريفات المحادثة بالأدوات التي يملك المستخدم صلاحيتها فقط، مع إعادة فحصها عند التنفيذ. تستخدم استعلامات ذات نطاق مؤسسي/فترة/صف، وترقيم وحد أقصى للنتائج والمقاطع، وتجنب جلب كل الأرشيف أو كل بيانات الطلاب. لا يُخزن سياق صلاحيات بين المستخدمين؛ أي تخزين مؤقت لاحق يجب أن يشمل المؤسسة والمستخدم/النطاق وإصدار البيانات في مفتاحه وأن يعاد تفويضه عند القراءة.

## Risks / Trade-offs

- [تغيير الرفض الافتراضي قد يعطل أدوات قديمة بتعريف صلاحية ناقص] → جرد جميع الأدوات واختبارها وتصحيح تعريفاتها قبل تفعيل المنع.
- [ربط المستخدم بحساب طالب أو تكليف معلم قد يكون ناقصًا أو متعددًا] → لا تخمين؛ اطلب توضيحًا أو أعد نتيجة صريحة بعدم توفر سياق موثوق.
- [المطابقة الحالية بين أسماء المستندات ومتطلبات الوثائق قد تفوت ملفات أو تطابقها خطأ] → توحيد مطابقة الرموز/الأنواع الوصفية والتحقق بحالات عربية وإنجليزية، وإظهار أن النتيجة تخص المتطلبات المطابقة المسجلة.
- [ملفات PDF الممسوحة أو الصيغ غير المدعومة قد لا تنتج نصًا قابلًا للبحث] → إظهار حالة عدم توفر النص وعدم توليد إجابة منسوبة إليها؛ لا يعتبر فشل الاستخراج نجاحًا.
- [تمرير مقاطع المناهج إلى مزود النموذج قد يكشف محتوى مؤسسيًا] → الالتزام بمزود المؤسسة المُهيأ، وإرسال المقاطع اللازمة فقط، واحترام صلاحية الوصول قبل الاسترجاع والإرسال.
- [الاستعلام عن نواقص مؤسسة كاملة قد ينتج حجمًا كبيرًا من البيانات] → صلاحية مناسبة، ترقيم وحدود نتائج وتجميع في قاعدة البيانات أو الخدمة، مع احترام نطاق الوحدة.

## Migration Plan

1. جرد كل أدوات AI وصلاحياتها واختبارات تنفيذها، ثم تصحيح التعريفات التي لا تملك صلاحية معروفة.
2. إضافة التفويض المغلق واختبارات الرفض قبل ربط الأدوات التعليمية الجديدة.
3. إضافة/توصيل سياق الطالب والمعلم واسترجاع المتطلبات والنصوص مع حدود النطاق والنتائج.
4. إطلاق أدوات القراءة والمراجعة وتوليد المسودات دون تغيير واجهات API الحالية للرسائل؛ توسيع بيانات الأدوات/النتائج بشكل متوافق.
5. عند فشل التحقق أو ظهور تراجع في الاسترجاع، تعطيل الأدوات الجديدة عبر قائمة الأدوات وإبقاء المحادثة العامة متاحة، دون فتح مسار تجاوز للصلاحيات.

## Initial Content Support

تدعم النسخة الأولى ملفات المناهج التي يمكن استخراج نصها مباشرة. لا يشمل النطاق OCR للصور أو ملفات PDF الممسوحة ضوئيًا؛ يجب إظهار هذه الملفات كغير قابلة للبحث وعدم نسبة إجابات إليها. يمكن إضافة OCR كتغيير مستقل لاحقًا.
