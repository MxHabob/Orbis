# Spec Delta

## Purpose

تتيح هذه القدرة للموظف المخول إعداد تذكير مالي مناسب وإرساله لجهات اتصال أولياء أمور الطلاب المؤهلين عبر تكاملات المؤسسة المرتبطة، دون تجاوز الصلاحيات أو إرسال رسائل جماعية غير مراجعة.

## ADDED Requirements

### Requirement: تحديد المستلمين ضمن صلاحيات المستخدم
The system MUST يحدد أولياء الأمور ووسائل الاتصال من العلاقات المسجلة للطلاب غير المسددين فقط بعد التحقق من صلاحيات قراءة المالية وقراءة أولياء الأمور والإشعارات، ويقصر القائمة على نطاق المستخدم.

#### Scenario: مستخدم يملك الصلاحيات والنطاق المناسبين
- **WHEN** يطلب مستخدم يملك `finance:read` و`guardian:read` و`notification:write` إعداد تذكير ضمن نطاقه
- **THEN** يحصر النظام المستلمين في أولياء أمور الطلاب ذوي الرصيد المستحق ووسائل الاتصال المؤهلة المسجلة لديهم

#### Scenario: إحدى الصلاحيات المطلوبة غير متوفرة
- **WHEN** لا يملك المستخدم أي صلاحية مطلوبة لتحديد المستلمين أو الإرسال
- **THEN** يرفض النظام العملية قبل إرجاع قائمة المستلمين أو بياناتهم

#### Scenario: لا توجد وسيلة اتصال صالحة أو مزود متاح
- **WHEN** لا يملك بعض أولياء الأمور وسيلة اتصال للقناة المختارة أو لا يوجد تكامل نشط مدعوم
- **THEN** يستبعد النظام غير المؤهلين من الإرسال ويعرض عددهم وسبب الاستبعاد دون محاولة إرسال أو رجوع صامت إلى مزود آخر

### Requirement: اختيار قناة وتكامل مؤسسي مدعوم
The system MUST يتيح للمستخدم اختيار تكامل مرتبط ومفعّل وصحي يعلن دعمه للقناة ويملك محول إرسال فعليًا، ويرفض بدء الدفعة إذا تغيرت حالة التكامل أو تعذر التحقق من صلاحيته.

#### Scenario: اختيار مزود وقناة متوافقين
- **WHEN** يختار المستخدم قناة وتكاملًا نشطًا مدعومًا للمؤسسة
- **THEN** يربط النظام معاينة الدفعة والإرسال بمعرف التكامل المختار ولا يستبدله تلقائيًا بالتكامل الافتراضي

#### Scenario: التكامل غير مرتبط أو لا يدعم القناة
- **WHEN** يختار المستخدم تكاملًا غير مرتبط أو معطّلًا أو لا يملك محولًا فعليًا للقناة
- **THEN** يمنع النظام الإرسال ويوضح ضرورة ربط تكامل متوافق وإجراء فحص الاتصال بنجاح

### Requirement: مراجعة نهائية إلزامية للرسائل الجماعية
The system MUST يعرض معاينة نهائية لمجموعة المستلمين والقناة والتكامل ونص الرسالة ومحتواها المخصص قبل إرسال أي رسالة، ويتطلب موافقة صريحة منفصلة مرتبطة بهذه المعاينة.

#### Scenario: مراجعة الدفعة قبل الإرسال
- **WHEN** ينشئ الوكيل مسودة رسالة أو يحدد مجموعة مستلمين
- **THEN** يعرض النص النهائي وأسماء الطلاب/أولياء الأمور المؤهلين وبيانات الاتصال المقنّعة والقناة والتكامل وأعداد المستبعدين، ولا يرسل بعد

#### Scenario: المستخدم يوافق على المعاينة ذاتها
- **WHEN** يؤكد المستخدم صراحةً المعاينة التي تتضمن النص والمستلمين والقناة والتكامل
- **THEN** يعيد النظام التحقق من الصلاحيات والتكامل والأرصدة، ثم ينشئ مهمة إرسال للدُفعة المعتمدة فقط

#### Scenario: تغير النص أو المستلمون بعد المعاينة
- **WHEN** يتغير النص أو مجموعة المستلمين أو القناة أو التكامل بعد المعاينة
- **THEN** يبطل النظام الموافقة السابقة ويطلب معاينة وموافقة جديدة قبل الإرسال

#### Scenario: المستخدم يلغي أو لا يؤكد
- **WHEN** يرفض المستخدم المعاينة أو لا يقدم موافقة صريحة
- **THEN** لا يرسل النظام أي رسالة ويبقي العملية مسودة أو ملغاة

### Requirement: إرسال خلفي آمن وقابل للتتبع
The system MUST ينفذ الدفعات الكبيرة في الخلفية بحدود إرسال ومعدل معلومة، ويسجل نتيجة كل مستلم ويربط العملية بالمنشئ والموافقة والتكامل والقناة.

#### Scenario: متابعة دفعة جارية
- **WHEN** يبدأ إرسال مجموعة رسائل
- **THEN** يعيد النظام معرّف مهمة وحالة قابلة للاستعلام ويعرض التقدم والنجاح والفشل دون تعليق المحادثة أو الواجهة

#### Scenario: فشل جزئي أو إعادة محاولة
- **WHEN** يفشل الإرسال لبعض المستلمين
- **THEN** يسجل النظام حالة كل مستلم وسبب الفشل، ولا يعيد إرسال الناجح عند إعادة محاولة العناصر الفاشلة

#### Scenario: تعذر الإرسال قبل التنفيذ
- **WHEN** يفشل التحقق من صلاحية أو تكامل أو اتصال قبل بدء الدفعة
- **THEN** يوقف النظام الدفعة ويعرض خطأ صريحًا دون الإبلاغ عن نجاح أو إرسال عبر مزود بديل

### Requirement: تقليل البيانات المالية في نصوص الإشعارات
The system MUST لا يضيف مبالغ أو تفاصيل مالية شخصية تلقائيًا إلى رسالة ولي الأمر، ويشترط ظهور أي معلومة مالية مخصصة في المعاينة النهائية قبل الإرسال.

#### Scenario: إنشاء تذكير عام
- **WHEN** يطلب المستخدم تذكيرًا عامًا بالسداد
- **THEN** يصوغ النظام رسالة محترمة ومحايدة لا تكشف مبلغًا أو تفاصيل مالية فردية افتراضيًا

#### Scenario: رسالة مخصصة تتضمن معلومة مالية
- **WHEN** يضيف المستخدم معلومة مالية أو متغيرًا مخصصًا لطالب إلى نص الرسالة
- **THEN** يعرض النظام القيمة الفعلية لكل مستلم في المعاينة ويشترط الموافقة عليها ضمن الدفعة نفسها
