# الإطار الأكاديمي المرن

## حدود النموذج

يمثل المخطط الأكاديمي الجديد التقويم والفترات وعروض المقررات ومحاولات التسجيل ككيانات مستقلة. نوع المؤسسة لا يغيّر بنية المحرك أو يفرض وجود شهر أو فصل أو سنة.

```text
organization
├── academic_calendars (0..*)
│   └── academic_calendar_periods (0..*)
│       ├── period_type_id ── academic_period_types
│       ├── parent_id ─────── academic_calendar_periods (اختياري)
│       └── course_offerings (اختياري)
├── courses (0..*)
│   ├── unit_id ──────────── org_units (اختياري)
│   └── course_offerings (0..*)
│       └── course_enrollments (0..*)
│           └── student_id ─ students
└── academic_period_types (0..*)
```

كل التقويمات وأنواع الفترات والفترات والمقررات والعروض والتسجيلات لها `org_id`. الفترات وعروض المقررات اختيارية التواريخ؛ و`course_offerings.period_id` اختياري للدورات المستمرة أو غير المقسمة زمنيًا. العرض يربط كتالوج المقرر بسياق تقديم مستقل، والتسجيل يربط المتعلم بعرض محدد ورقم محاولة. لا يُستخدم تسجيل المؤسسة العام بدل محاولة المقرر.

تفرض المفاتيح الخارجية وجود المراجع، ويفرض قيد فريد رقم المحاولة ضمن المؤسسة والعرض والمتعلم. تتحقق خدمات التطبيق أيضًا من نطاق المؤسسة، ومن انتماء الفترة إلى التقويم نفسه عند إنشاء علاقة أب، ومن انتماء الوحدة أو المقرر أو العرض أو المتعلم إلى المؤسسة المطلوبة. لأن هذه القيود العابرة للمؤسسة لا يعبر عنها المفتاح المنفرد الحالي، يجب أن تمر الكتابة عبر الخدمات؛ وتضيف اختبارات التكامل تحققًا مباشرًا للقيود في SQLite وPostgreSQL.

تبدأ التقويمات بحالة `planning`، والعروض بحالة `draft`؛ لا يؤدي إنشاء إعداد أو عرض إلى تفعيل بيانات تشغيلية أو إنشاء مقررات أو متعلمين تلقائيًا.

## التوافق مع الجداول الحالية

الترحيل `m20240115_000001_academic_framework_foundations` إضافي وغير هدّام. ينشئ الجداول الجديدة ولا ينسخ أو يحذف أو يعيد تفسير سجلات الجداول القديمة. يظل مسار القراءة الحالي مصدرًا لعملائه خلال فترة التوافق، وتكتب واجهات الإطار الجديد إلى الجداول الجديدة.

| النموذج الحالي | معناه الحالي | حد التوافق مع الإطار الجديد |
|---|---|---|
| `academic_years` | سنة ذات بداية ونهاية وحالة قفل ومعلومات أرشفة | لا تتحول تلقائيًا إلى `academic_calendars`؛ يختار المسؤول التقويم المقابل صراحةً إذا كان التطابق صحيحًا. |
| `academic_periods` | فترة إلزامية مرتبطة بـ`year_id` وبنوع ووظائف تشغيلية مثل التدريس والتسجيل والدرجات والاختبارات | تبقى متاحة لمساراتها القديمة. تنقل الفترات إلى `academic_calendar_periods` فقط بعد اختيار تقويم ونوع فترة وعلاقات صالحة؛ لا تستنتج شهور أو فصولًا من الاسم. |
| `class_subjects` | إسناد مادة إلى صف وفترة ومعلم مع إعداد تقييم | لا تتحول تلقائيًا إلى `course_offerings`: فإسناد المادة إلى صف ليس بالضرورة كتالوج مقرر وعرضًا مستقلًا. يتطلب الربط تحديد المقرر والعرض والوحدة والفترة المقصودة. |
| `enrollments` | تسجيل مؤسسي للمتعلم في فترة وصف اختياري ونمط دراسة وإعفاءات | لا يتحول إلى `course_enrollments`: التسجيل الجديد خاص بعرض مقرر ورقم محاولة. ينشأ فقط عندما يكون العرض والعلاقة بالمتعلم مؤكدين، مع إبقاء تسجيل المؤسسة الأصلي. |

لا تُحذف أعمدة أو جداول التوافق في هذه المرحلة، ولا تُعدّل درجات تاريخية أو نتائج معتمدة عند الربط. تحويل بيانات قديمة يكون عملية مراجعة صريحة قابلة للتدقيق، ويُنفذ ضمن خطة توافق مستقلة قبل إيقاف المسارات القديمة. محولات API القديمة للفصل والسنة تبقى خارج هذا المخطط الأساسي، وتُغطى ضمن مرحلة توافق API.

## تغطية التحقق الحالية

- `creates_academic_foundation_tables_on_sqlite` يشغل ترحيل الجداول الجديدة مرتين على SQLite ويتحقق من وجودها.
- `generates_postgres_schema_for_academic_foundations` يتحقق من توليد مخطط PostgreSQL للفترات؛ التشغيل الفعلي على PostgreSQL مؤجل إلى اختبار التكامل في المهمة 6.1.
- `offering_can_be_created_without_an_academic_period` يتحقق من صلاحية العرض دون فترة.
- `enrollment_rejects_a_student_from_another_organization` و`enrollment_rejects_a_duplicate_course_attempt` يتحققان من رفض مرجع المؤسسة المتضارب ومحاولة التسجيل المكررة.
- `parent_period_must_belong_to_the_same_calendar` و`child_range_must_fit_parent_range` يغطيان تحقق علاقة الأب ونطاق التواريخ.

## حدود المرحلة

هذا المخطط لا يعرّف بعد مقاييس التقييم أو درجاتها أو إصدارات قواعد الحساب والنتائج المعتمدة. ستُربط تلك السجلات لاحقًا بعرض المقرر والتسجيل والفترة عبر معرفات صريحة، من دون إضافة افتراضات شهرية أو ملخصات سنوية لهذا النموذج.
