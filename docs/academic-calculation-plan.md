# خطة الحساب الأكاديمي typed

## الخطة والمدخلات

تتكون `CalculationPlan` من إصدار موجب ومدخلات ومخرجات مسماة. كل مدخل ومخرج رقمي يحمل وحدة معلنة؛ وتعرّف وحدة `score` هوية المقياس في `scale`، لذا لا يمكن جمع نقاط من مقياسين مختلفين قبل تحويلهما صراحة. يقبل المدخل حدًا أدنى أو أعلى اختياريًا، ويحدد `is_required` ما إذا كان غيابه خطأ.

```json
{
  "version": 2,
  "inputs": [
    {
      "name": "practical",
      "unit": { "type": "score", "scale": "out_of_20" },
      "minimum": 0,
      "maximum": 20,
      "is_required": true
    }
  ],
  "outputs": [
    {
      "name": "percentage",
      "unit": { "type": "score", "scale": "percentage" },
      "expression": {
        "type": "convert",
        "value": { "type": "variable", "name": "practical" },
        "from": { "type": "score", "scale": "out_of_20" },
        "to": { "type": "score", "scale": "percentage" },
        "factor": 5,
        "offset": 0
      },
      "rounding": { "mode": "round_half_up", "decimal_places": 2 }
    }
  ]
}
```

الخطة عقد Rust/Serde typed (`CalculationPlan`, `CalculationInput`, `CalculationOutput`, `AstNode`) وليست إعداد JSON عامًّا. يمكن للمخرج الإشارة إلى مدخل أو إلى مخرج أسبق في ترتيب تعريف الخطة؛ لا تقبل المراجع المجهولة أو المراجع إلى مخرج لاحق.

## AST والقيود

المشغلات المدعومة هي `literal` و`measure_literal` و`variable` و`add` و`subtract` و`multiply` و`divide` و`min` و`max` و`average` و`weighted_sum` و`convert`. لا توجد دوال أو شيفرات تنفيذية يرسلها العميل.

- تتطلب عمليات الجمع والطرح والمتوسط والحدين الأعلى/الأدنى وحدات متطابقة.
- يسمح الضرب بعامل واحد ذي وحدة `dimensionless` كحد أقصى؛ وتنتج القسمة بين وحدتين متماثلتين قيمة بلا وحدة، بينما تحفظ القسمة على قيمة بلا وحدة وحدة البسط.
- يتطلب `convert` وحدة مصدر تطابق التعبير، ويحدد وحدة الهدف ومعاملًا وإزاحة صريحين.
- أوزان `weighted_sum` غير سالبة، ويجب أن يكون مجموعها موجبًا. `normalize: true` يقسم المجموع الموزون على مجموع الأوزان.
- ترفض الخطة العمليات بلا operands، والمراجع الخاطئة، والمدخلات خارج الحدود، والقسمة على صفر، وتجاوز Decimal، ووحدات النتائج غير المطابقة.
- الحد الأقصى لعمق AST هو 64، والحد الأعلى للتقريب 28 منزلة عشرية. تطبق قاعدة التقريب مرة على ناتج كل مخرج، لا على المدخلات الوسيطة.

تغطي اختبارات المحرك تحويل مقياس من 20 إلى 100، ومتوسطًا موزونًا، وحدود المدخلات، والمراجع والوحدات غير المتوافقة، والقسمة على صفر. تخزن `version` مع النتيجة المحسوبة لاحقًا حتى يظل تفسير المخرجات مرتبطًا بإصدار القواعد المنتج لها.

## ملفات قبول تعليمية

تتحقق `institutional_profiles_cover_optional_months_credits_and_competencies` من اختلاف البنية التعليمية بتغيير البيانات والخطة فقط:

| الملف | الخطة | المدخلات | الناتج المتوقع |
|---|---|---|---|
| مدرسة بتقييم شهري | متوسط الشهرين | 80، 90 | 85 |
| مدرسة بلا تقييم شهري | واجبات 40% واختبار 60% | 80، 90 | 86 |
| جامعة | متوسط نقاط المقررات موزونًا بالساعات | 3.7 لأربع ساعات، 3.3 لساعتين | 3.5666666666666666666666666667 |
| معهد | مخرج عملي ومخرج كفاءة مستقلان بوحدتين معلنتين | عملي 4.5/5، كفاءة 3/4 | يحتفظ كل مخرج بوحدته وقيمته |

لا يفرض أي ملف وجود مخرج نهائي إضافي؛ التقرير هو الذي يختار المخرجات التي يعرضها. اختبارات القبول هذه تثبت الحسابات الأساسية ولا تعني أن ملفات الإعداد مخزنة أو مفعّلة تلقائيًا للمؤسسات؛ إنشاء ملفات Bootstrap قابلة للتخصيص جزء منفصل من التنفيذ.

## قواعد النتائج الاختيارية

تعرف `OutcomePolicy` وحدة النتيجة وحد النجاح والتكريم وحدود نطاقات التقدير. حدود النجاح والتكريم شاملة (`score >= threshold`)، ويختار التقدير أعلى حد أدنى لا يتجاوز النتيجة. الترتيب الدقيق يعيد `Decimal` ويدعم الترتيب التنافسي والكثيف ومتوسط مراكز التعادل. تبقى محولات التقرير القديم ذات الرتبة الصحيحة منفصلة ولا تقرب الرتبة الكسرية بصمت.

تحسب دالة المعدل الموزون متوسطًا على الأوزان المدرجة فقط، مثل الساعات المعتمدة؛ تتطلب وزنًا إجماليًا موجبًا وتقبل قاعدة تقريب اختيارية. لا تحسب هذه الدوال معدلًا أو ترتيبًا تلقائيًا ما لم تطلبهما السياسة.

## إصدارات النتائج

تُخزَّن النتيجة المحسوبة كـ `ResultSnapshot` منفصل، لا كملف قابل للتعديل على مكانه. يحمل كل لقطة:

- معرف المتعلم والمؤسسة ونطاق النتيجة (مادة/فترة/سنة)
- `policy_version` و`revision` الذي يثبت النسخة الفعلية من القواعد
- مراجع المدخلات (`ResultInputReference`) مع إصداراتها المستخدمة
- وقت الحساب، ووقت الاعتماد، ومعرّف المعتمد عند اعتمادها
- `payload` JSON typed للنتائج المحسوبة، بحيث تبقى لقطة سابقة قابلة لإعادة العرض بعد تحديث السياسة

يُنشئ كل تصحيح أو إعادة حساب نسخة جديدة تربطها بـ `parent_snapshot_id` لتكوين سلسلة مراجعات غير قابلة للتبديل مع الاحتفاظ بالنسخة السابقة. لا تمسّ منطق المحرك القابل للتوسيع في هذه الطبقة، بل يظل هو المصدر الوحيد للحساب، بينما الطبقة التالية تتعامل مع السجل والاعتماد والتصحيح التاريخي.

## توافق الحسابات القديمة

ما زالت DTOs الفصل والسنة القديمة مطلوبة مؤقتًا لمسارات القراءة الحالية. توابعها محولات توافق تبني خطة وتستدعي `calculate_plan` بدل تنفيذ محرك تجميع موازٍ. لا تستخدم هذه المحولات لتصميم سياسة مؤسسة جديدة؛ ستُستبدل تدريجيًا بعقود النتائج المعرفة في السياسة وعقود API الجديدة.
